# 群文件操作说明

群文件工具从当前消息获取群号。先查询目录，使用接口实际返回的 ID 执行后续操作；
不要根据文件名、文件夹名或旧消息推测 ID。

## 查询文件与文件夹

`list_group_files` 参数：

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `folder_id` | `/` | 根目录为 `/`；查询文件夹时传列表中的 `folder_id` |
| `file_count` | `50` | 正整数，传给 NapCat 的本次查询数量 |

例如：

```json
{"folder_id": "/", "file_count": 50}
```

查询指定文件夹：

```json
{"folder_id": "列表返回的文件夹ID", "file_count": 100}
```

返回内容包括：

- 文件：名称、`file_id`、大小、上传日期、原始上传时间戳、`busid`。
- 文件夹：名称、`folder_id`、文件数量、创建日期、原始创建时间戳、创建者 QQ。
- 当前目录：`current_parent_directory`，可用于移动、重命名。

可读日期标注 UTC，原始时间戳同时保留。缺失或无法解析的日期显示为未知。
只有文件夹、没有文件的目录，也会正常列出文件夹。

插件会展示本次接口返回的文件和文件夹，不再只显示前 20 个文件。
`file_count` 是请求数量；返回数量仍受 NapCat 版本及底层接口影响，不能据此认定已经取完全部群文件。
查询一个目录不会自动递归读取其子目录，需要继续传入相应 `folder_id`。

## 常用工具参数

以下参数不含自动从当前消息获取的群号。

| 工具 | 参数 | 说明 |
|------|------|------|
| `upload_group_file` | `file_path`、可选 `file_name`、`folder_id` | 上传本地文件，`folder_id` 可指定目标文件夹，默认根目录 |
| `delete_group_file` | `file_id`、可选 `busid` | `busid` 应来自同一文件的列表结果 |
| `create_group_file_folder` | `folder_name` | 在根目录创建文件夹，解析接口返回的嵌套结果 |
| `delete_group_folder` | `folder_id` | 删除指定群文件夹，可能连带删除其中的文件 |
| `move_group_file` | `file_id`、`current_parent_directory`、`target_parent_directory` | 当前目录和目标目录均为目录 ID，根目录填 `/` |
| `rename_group_file` | `file_id`、`current_parent_directory`、`new_name` | 当前父目录必须与文件所在目录一致 |
| `get_group_file_url` | `file_id`、可选 `busid` | 获取实际下载 URL；`busid` 用于接口兼容 |
| `trans_group_file` | `file_id` | 提交 NapCat 传输请求；该接口不接受目标群参数 |

移动和重命名的字段名是 `current_parent_directory`、`target_parent_directory`。
这些名称与 NapCat 详细接口文档和当前源码一致。

### 上传后的 ID

NapCat 上传接口返回的 `file_id` 可能是原始文件 UUID，与文件列表中的操作 ID 不同。
上传成功后重新调用 `list_group_files`，从目标目录取得新的 `file_id` 和 `busid`，
再进行删除、移动、重命名或获取 URL。

NapCat 的操作 ID 可能依赖进程内缓存。重启、缓存过期或文件发生变化后，旧 ID 可能失效；
出现无效 ID 错误时重新查询目录。不要手动拼接、截断或转换 ID。

### 获取下载 URL 与传输请求

需要下载链接时调用 `get_group_file_url`。它返回 NapCat 提供的真实 URL，
插件不会将“传输请求成功”当作已经获得下载链接或完成下载。

`trans_group_file` 仅报告 NapCat 是否接受并完成该接口请求，不返回跨群转发承诺。
移动、重命名、传输和获取群文件 URL 等接口还可能依赖 NapCat 的 packet backend；
如果返回 backend 不可用等错误，应根据 NapCat 启动日志与配置排查。

## 管理员命令

命令保留原有 AstrBot 管理员权限检查。

| 命令 | 用法 |
|------|------|
| 列表 | `/list_files [folder_id] [file_count]` |
| 删除文件 | `/delete_group_file <file_id> [busid]` |
| 获取下载 URL | `/get_group_file_url <file_id> [busid]` |
| 上传文件 | `/upload_file <路径> [文件名]` |
| 创建文件夹 | `/create_folder <名称>` |
| 删除文件夹 | `/del_folder <ID>` |
| 移动文件 | `/move_group_file <file_id> <当前目录ID> <目标目录ID>` |
| 重命名文件 | `/rename_group_file <file_id> <当前目录ID> <新名称>` |
| 传输请求 | `/trans_group_file <file_id>` |

例如查询根目录 100 条内容：

```text
/list_files / 100
```

旧版无参数 `/list_files` 仍查询根目录，默认请求 50 条。
上传到指定子目录可使用 `upload_group_file` 工具的 `folder_id` 参数。

## 响应校验与隐私模式

不同客户端可能返回已经解包的业务数据，也可能返回包含 `status`、`retcode`、`data` 的 OneBot 响应信封。
群文件工具兼容这两种形态，并检查业务层的失败信息。
接口 HTTP 状态为 200、调用没有抛异常，都不单独代表操作成功；
例如删除接口的非零 `retCode` 或逐文件失败结果仍应作为失败报告。

隐私模式保留由群文件工具确认的操作 ID 与下载 URL，使它们可用于后续操作；
群号、创建者 QQ 等身份信息继续按原有规则脱敏。
日期使用可读文本，避免原始长数字时间戳被脱敏后无法识别上传日期。
